# 技能管理器 · Codex Skill Manager

**用中文看懂已经安装的能力，知道自己用过什么，再决定保留什么。**

简体中文（默认） · [English](README.en.md)

这是一个运行在 **Codex 桌面客户端**里的插件。它把插件、应用、MCP 服务、技能和命令放在一个中文界面里，帮助你理解用途、查看安装来源与使用记录，并完成日常管理。

## 为什么创建它

我是个英语文盲，很多英文单词、英文简介看不懂。

但无论是 Codex 自带的能力，还是后来安装的技能和插件，英文名称和说明都很常见。我经常遇到几个问题：我到底装了什么？它能做什么？做当前任务该选哪个技能？装了很久却很少使用的东西，要不要留下？

所以我做了这个插件，先解决自己的需要：**方便查看，帮助理解，知道使用情况，也方便管理。** 如果你也遇到这些问题，希望它能帮上忙。

## 可以做什么

| 能力 | 你能看到或操作的内容 |
|---|---|
| 统一清单 | 查看插件、应用、MCP、技能和可发现的命令声明 |
| 中文说明 | 名称、用途、适用场景、需要的输入、产出、权限与依赖、关闭或移除的影响 |
| 安装来源 | 查看所属插件或已记录的技能仓库，按同一来源筛选；来源不明时明确说明 |
| 位置和范围 | 查看加载入口、实际路径、链接关系，区分个人环境和指定项目 |
| 使用情况 | 最近 30/90 天的真实工具调用、技能实际使用记录、最近使用时间，以及资料充分时的使用频率 |
| 日常管理 | 搜索、筛选、查看详情、启用、关闭；在支持且状态已确认时卸载插件、移除技能入口或 MCP 配置 |
| 异常处理 | 慢查询和某一来源读取失败时保留可用内容，把未知标成待确认，避免把读取失败误当成卸载 |

中文说明独立保存，不修改被管理插件或技能的原文。**这是一个管理与判断工具，不会自动替你清理“低频”内容。**

## 一条命令安装

需要 **Node.js 24+（含 npm/npx）、Git，以及支持 `codex plugin` 命令的 Codex**。目前实际验证环境为 Windows + Codex 桌面客户端；其他系统尚未完成真实客户端验收。

```sh
npx --yes github:maple192600-LI/codex-skill-manager install
```

安装器从 GitHub 获取，调用 Codex 原生命令注册本仓库的插件市场并安装 `skill-manager`。运行包已经构建好，普通安装无需自己编译。**本项目目前通过 GitHub 分发，尚未发布到 npm 注册表。**

安装完成后重启 Codex，再对 agent 说：

```text
打开技能管理器。
```

已经从本市场安装过时，重复执行不会改变当前的启用或关闭状态。如果检测到其他来源的同名插件，会保留原安装并停止，避免重复或覆盖。

```text
如果有其他来源的同名插件，保留原安装并告诉我。
安装后检查原生安装记录，告诉我是否需要重启；重启后再打开真实侧栏确认加载。
```

### 手动安装与检查

```sh
codex plugin marketplace add maple192600-LI/codex-skill-manager --ref main

```


细节见 [安装与验收](docs/INSTALL.md)。采用 Codex 的[仓库插件市场机制](https://developers.openai.com/plugins/build/plugins)，`npx` 的执行方式见 [npm 官方文档](https://docs.npmjs.com/cli/v11/commands/npm-exec/)。

## “用过”是怎么判断的

**读取过技能说明，不等于实际用过技能。没有找到记录，也不等于从未使用。**

- 插件、应用和 MCP 按本机可读取的真实工具调用统计，不把发现工具或连接检查算成业务使用。
- 技能只统计 agent 实际采用后提交的完整 `SKILL.md` 路径记录。同一轮同一技能记一次；计划使用、只读说明、历史文字推断都不计入。
- 技能记录需要 agent 配合提交。安装器不会自动修改你的全局规则。可按 [启用实际技能记录](docs/SKILL_USAGE.md) 自行选择配置；配置前的历史不能凭空还原。
- 记录不完整时，已确认次数标“至少”，不补造使用百分比，不归为“从未使用”。资料完整时，技能频率按使用天数占对应范围活跃天数计算。
- 项目技能的频率只看对应项目；使用次数、使用聊天数和活跃天数是不同指标。

## 管理边界

- **关闭与卸载分开。** 插件附带技能可在条件允许时单独关闭；“卸载所属插件”会先说明整个插件及附带内容的影响，再要求确认。
- 自带技能、默认提供插件、组织限制或暂未确认状态，可能只允许部分操作。页面说明具体原因，不把这些情况统一说成没有权限。
- 普通独立技能移除加载入口时保留可恢复内容；移除链接只影响选定入口；移除 MCP 配置不等于删除服务程序。
- 已单独连接的应用与插件安装是两件事。应用断开连接仍应使用 Codex 支持的原生设置。
- 页面显示的是本次查询环境的安装和有效配置；已经打开的聊天可能需要重新加载。

## 本地数据与模型使用

清单、中文说明缓存和统计保存在本机。本插件没有自己的遥测或上传聊天记录的服务。历史统计在本机读取 Codex 记录，不需要你提供第三方账号。

**补齐中文说明会调用你当前配置的 Codex 模型**，发送待翻译的名称、说明和技能文档，可能消耗模型额度；这些资料若含私有内容，也会交给该模型处理。统计在本地完成，不代表翻译完全离线。不要在未获许可时处理他人的私有技能文档。

## 开发

```sh
npm ci
npm --prefix ui ci
npm run build
npm test
```

服务入口：`server/server.bundle.mjs`；界面源码：`ui/src`；共享状态与管理规则：`shared`。测试包含隔离的原生配置与插件流程；需要可用的 Codex CLI。不要在正在使用的安装上做卸载测试。

本仓库发布的是 Codex 本地插件，交互界面依赖 Codex 宿主；不是通用网页，也尚未适配 Claude Code。当前版本的功能和限制见 [CHANGELOG](CHANGELOG.md)。
